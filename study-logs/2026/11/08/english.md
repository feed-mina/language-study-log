# 실무 영어 5문장: 브라우저 저장과 기본기 점검

브라우저 저장 상태 확인, SQL 결과와 정렬 구분, 기술 선택의 장단점 설명, 경계값 테스트, 오래된 캐시 갱신에 자연스럽게 사용할 수 있는 실무 영어 표현을 연습합니다.

대표 말하기 문장: If the cached value is stale, the application should fetch a fresh copy.

대표 문장 뜻: 캐시된 값이 오래되었다면 애플리케이션은 새로운 복사본을 가져와야 합니다.

## 전체 학습 항목

### 1. Let's verify what is stored in the browser before we change the session logic.

- 뜻: 세션 로직을 변경하기 전에 브라우저에 무엇이 저장되어 있는지 확인합시다.
- 설명: 문법: Let's + 동사원형은 함께 행동하자는 제안이며, what is stored는 수동태가 들어간 간접의문문입니다. 발음: verify는 ‘베러파이’, stored는 ‘스토어드’, session은 ‘세션’에 가깝습니다. 사용: 세션·로컬 저장소 관련 로직을 수정하기 전에 현재 저장 상태를 함께 점검할 때 씁니다.

### 2. The query returns the correct rows, but the sort order is inconsistent.

- 뜻: 쿼리는 올바른 행을 반환하지만 정렬 순서는 일관되지 않습니다.
- 설명: 문법: but은 앞뒤의 대조를 연결하고, 단수 주어 the query와 the sort order에 맞춰 returns와 is를 씁니다. 발음: query는 ‘쿼리’, rows는 ‘로우즈’, inconsistent는 ‘인컨시스턴트’에 가깝습니다. 사용: SQL 결과 자체는 맞지만 정렬이 예상과 다를 때 문제를 정확히 구분해 설명하는 표현입니다.

### 3. Could you explain the trade-off in plain terms before we choose an option?

- 뜻: 옵션을 선택하기 전에 장단점을 쉬운 말로 설명해 주시겠어요?
- 설명: 문법: Could you + 동사원형은 정중한 요청이고, before 뒤에는 주어와 동사가 있는 시간 부사절이 옵니다. 발음: trade-off는 ‘트레이드오프’, plain terms는 ‘플레인 텀즈’에 가깝습니다. 사용: 회의에서 기술 선택의 장단점을 비전문가도 이해하기 쉽게 설명해 달라고 요청할 때 씁니다.

### 4. I'll add a small test case for each boundary condition.

- 뜻: 각 경계 조건에 대해 작은 테스트 케이스를 추가하겠습니다.
- 설명: 문법: I'll은 I will의 축약형으로 즉석 결정이나 약속을 나타내며, each 뒤에는 단수 명사 boundary condition이 옵니다. 발음: boundary는 ‘바운더리’, condition은 ‘컨디션’에 가깝습니다. 사용: 빈 값, 최솟값, 최댓값 같은 경계 상황을 하나씩 테스트하겠다고 작업 계획을 공유할 때 씁니다.

### 5. If the cached value is stale, the application should fetch a fresh copy.

- 뜻: 캐시된 값이 오래되었다면 애플리케이션은 새로운 복사본을 가져와야 합니다.
- 설명: 문법: If + 현재형, 주절의 should + 동사원형 구조로 조건과 권장 동작을 말합니다. cached는 과거분사가 형용사처럼 value를 꾸밉니다. 발음: cached는 ‘캐시드’, stale은 ‘스테일’, fetch는 ‘페치’에 가깝습니다. 사용: 캐시된 데이터가 오래되었을 때 최신 값을 다시 불러오는 동작을 설명할 때 씁니다.
