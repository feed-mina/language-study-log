# 실무 영어 5문장: 확장성·긴급 수정·비동기 오류

지속 부하에서의 확장성, 긴급 수정과 리팩터링 범위 분리, 비동기 작업 시작 실패, 임시 안전장치, 기술 선택의 장단점 정리에 자연스럽게 사용할 수 있는 실무 영어 표현을 연습합니다.

**대표 말하기 문장:** I'll summarize the trade-offs so we can make an informed decision.

**대표 문장 뜻:** 충분한 정보를 바탕으로 결정할 수 있도록 장단점을 요약하겠습니다.

## 전체 학습 항목

### 1. 지속 부하에서 확장성 설명

**영어 문장:** The current implementation works, but it does not scale well under sustained load.

**한국어 뜻:** 현재 구현은 작동하지만 지속적인 부하에서는 확장성이 좋지 않습니다.

**설명:** 문법: but은 정상 작동과 확장성 한계를 대조하고, scale well은 규모나 부하가 커져도 잘 대응한다는 뜻입니다. 발음: implementation은 ‘임플러멘테이션’, sustained는 ‘서스테인드’에 가깝습니다. 맥락: 성능 검토에서 기능은 맞지만 장시간 높은 부하를 견디기 어렵다고 설명할 때 씁니다.

### 2. 긴급 수정과 리팩터링 분리

**영어 문장:** Could we separate the urgent fix from the broader refactoring effort?

**한국어 뜻:** 긴급 수정과 더 광범위한 리팩터링 작업을 분리할 수 있을까요?

**설명:** 문법: Could we는 협업적인 제안이고, separate A from B는 A와 B를 구분하거나 분리한다는 구조입니다. 발음: broader는 ‘브로더’, refactoring은 ‘리팩터링’에 가깝습니다. 맥락: 회의에서 즉시 필요한 수정과 장기적인 코드 개선의 범위를 나눌 때 자연스럽습니다.

### 3. 비동기 작업 시작 실패 보고

**영어 문장:** The request was accepted, but the background job never started.

**한국어 뜻:** 요청은 접수됐지만 백그라운드 작업은 시작되지 않았습니다.

**설명:** 문법: was accepted는 과거 수동태이고, but은 접수 성공과 후속 작업 실패를 대조합니다. 발음: accepted는 ‘억셉티드’, background는 ‘백그라운드’에 가깝습니다. 맥락: 비동기 처리에서 앞 단계는 성공했지만 작업 실행이 이어지지 않은 오류를 보고할 때 씁니다.

### 4. 임시 안전장치 제안

**영어 문장:** Let's add a temporary safeguard while we investigate the underlying cause.

**한국어 뜻:** 근본 원인을 조사하는 동안 임시 안전장치를 추가합시다.

**설명:** 문법: Let’s 뒤에는 동사원형이 오며, while은 두 행동이 같은 기간에 진행됨을 나타냅니다. 발음: safeguard는 ‘세이프가드’, underlying은 ‘언더라잉’에 가깝습니다. 맥락: 장애 원인을 분석하는 동안 피해를 줄일 임시 보호 조치를 제안할 때 유용합니다.

### 5. 장단점 정리 후 의사결정

**영어 문장:** I'll summarize the trade-offs so we can make an informed decision.

**한국어 뜻:** 충분한 정보를 바탕으로 결정할 수 있도록 장단점을 요약하겠습니다.

**설명:** 문법: so + 주어 + can은 앞 행동의 목적이나 그로 인해 가능해지는 결과를 나타냅니다. informed decision은 필요한 정보를 검토한 뒤 내리는 결정입니다. 발음: trade-offs는 ‘트레이드오프스’, informed는 ‘인폼드’에 가깝습니다. 맥락: 회의에서 여러 선택지의 장단점을 정리한 뒤 결정을 돕겠다고 말할 때 씁니다.
