# 실무 영어 5문장: 성능 개선·오류 재현·결정 기록·단계 검증·일정 영향

불필요한 작업을 제거한 뒤의 성능 개선을 설명하고, 깨끗한 환경에서 오류를 재현하자고 제안하는 표현을 연습합니다. 결정 근거 기록, 단계별 결과 검증, 지연이 일정과 범위에 미치는 영향 설명도 함께 익힙니다.

## 대표 말하기 문장

- **Could we reproduce the issue in a clean environment before changing the code?**
- 코드를 변경하기 전에 깨끗한 환경에서 문제를 재현해 볼 수 있을까요?

## 전체 학습 항목

### 1. 성능 개선 원인 설명

**영어:** The response time improved after we removed an unnecessary network call.

**뜻:** 불필요한 네트워크 호출을 제거한 뒤 응답 시간이 개선되었습니다.

**설명:** `after + 주어 + 동사`는 한 동작이 끝난 뒤 생긴 결과를 연결합니다. `improved`와 `removed`는 모두 과거에 완료된 일을 나타냅니다. `unnecessary`는 /ʌnˈnesəseri/, `network`는 /ˈnetwɜːrk/로 발음합니다. 성능 측정 결과와 개선 원인을 함께 보고할 때 자연스럽습니다.

### 2. 깨끗한 환경에서 오류 재현

**영어:** Could we reproduce the issue in a clean environment before changing the code?

**뜻:** 코드를 변경하기 전에 깨끗한 환경에서 문제를 재현해 볼 수 있을까요?

**설명:** `Could we ...?`는 팀에 정중하게 공동 행동을 제안하는 표현입니다. `before + -ing`는 “~하기 전에”라는 뜻입니다. `reproduce`는 /ˌriːprəˈduːs/, `environment`는 /ɪnˈvaɪrənmənt/로 발음합니다. 기존 설정의 영향을 배제한 상태에서 오류를 먼저 확인하자고 제안할 때 씁니다.

### 3. 의사결정 근거 기록

**영어:** Let's document why we rejected the alternative, not just what we decided.

**뜻:** 무엇을 결정했는지만이 아니라 대안을 거부한 이유도 기록합시다.

**설명:** `Let's + 동사원형`은 함께 하자는 제안입니다. `why we rejected ...`와 `what we decided`는 각각 이유와 결정 내용을 나타내는 명사절입니다. `alternative`는 /ɔːlˈtɜːrnətɪv/, `rejected`는 /rɪˈdʒektɪd/로 발음합니다. 회의 결과뿐 아니라 판단 근거까지 남길 때 유용합니다.

### 4. 단계별 결과 검증

**영어:** I'll verify each step separately so we can identify where the result changes.

**뜻:** 결과가 어느 지점에서 달라지는지 찾을 수 있도록 각 단계를 따로 검증하겠습니다.

**설명:** `so + 주어 + can`은 목적이나 기대 결과를 나타냅니다. `where the result changes`는 변화 지점을 나타내는 간접의문문입니다. `separately`는 /ˈsepərətli/, `identify`는 /aɪˈdentɪfaɪ/로 발음합니다. 긴 처리 흐름에서 문제가 생기는 정확한 단계를 찾을 때 씁니다.

### 5. 일정과 범위의 영향 구분

**영어:** The delay affects the review date, but it does not change the delivery scope.

**뜻:** 그 지연은 검토 일정에는 영향을 주지만 납품 범위를 바꾸지는 않습니다.

**설명:** `affects A, but does not change B`는 영향이 있는 부분과 없는 부분을 대비합니다. 3인칭 단수 주어 `The delay`에 맞춰 `affects`와 `does`를 사용합니다. `review`는 /rɪˈvjuː/, `delivery`는 /dɪˈlɪvəri/로 발음합니다. 지연의 영향을 일정과 업무 범위로 나누어 설명할 때 적합합니다.
