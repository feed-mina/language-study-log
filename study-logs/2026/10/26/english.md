# 실무 영어 5문장: 통합 시험·작업 산정·데이터 이전·회의 집중·지표 비교

오늘은 단독 시험과 통합 흐름의 차이, 확정 작업과 미산정 작업의 구분, 안전한 데이터 이전, 회의 논점 집중, 배포 후 지표 비교를 설명하는 표현을 연습합니다.

## 전체 학습 항목

### 1. 단독 시험과 통합 시험 비교

**영어:** The test passes in isolation but fails when the full workflow runs.

**한국어 뜻:** 이 테스트는 단독으로 실행하면 통과하지만 전체 작업 흐름이 실행되면 실패합니다.

**설명:** `in isolation`은 다른 요소와 분리된 상태를 뜻합니다. 두 동사 `passes`와 `fails`를 `but`으로 대비했습니다. 미래에 반복될 수 있는 일반 조건을 말하므로 `when`절에 현재형 `runs`를 사용합니다. `isolation`은 “아이설레이션”, `workflow`는 “워크플로우”에 가깝습니다. 단위 시험은 통과하지만 통합 환경에서만 실패하는 상황을 설명할 때 씁니다.

### 2. 확정 작업과 미산정 작업 구분

**영어:** Could we separate confirmed work from items that still need estimation?

**한국어 뜻:** 확정된 작업과 아직 산정이 필요한 항목을 구분할 수 있을까요?

**설명:** `separate A from B`는 “A와 B를 분리하다”라는 뜻입니다. `that still need estimation`은 `items`를 꾸미는 관계절입니다. `confirmed`는 “컨펌드”, `estimation`은 “에스터메이션”에 가깝습니다. 일정 회의에서 확정 범위와 추가 분석이 필요한 범위를 나눌 때 사용합니다.

### 3. 안전한 데이터 이전

**영어:** We'll migrate the records in batches to avoid locking the table for too long.

**한국어 뜻:** 테이블이 너무 오래 잠기는 것을 피하기 위해 레코드를 여러 묶음으로 나누어 이전하겠습니다.

**설명:** `in batches`는 데이터를 한꺼번에 처리하지 않고 여러 묶음으로 나눈다는 뜻입니다. `to avoid`는 목적을 나타내며 `avoid` 뒤에는 동명사 `locking`이 옵니다. `migrate`는 “마이그레이트”, `batches`는 “배치즈”에 가깝습니다. 대량 데이터 이전이 서비스에 주는 영향을 줄이는 방법을 설명할 때 유용합니다.

### 4. 회의 논점 집중

**영어:** Let's keep this discussion focused on the release blocker.

**한국어 뜻:** 이번 논의는 배포를 막는 핵심 문제에 집중합시다.

**설명:** `keep + 목적어 + focused on`은 목적어가 특정 주제에 집중된 상태를 유지한다는 뜻입니다. `Let's`는 함께 행동하자는 제안입니다. `discussion`은 “디스커션”, `blocker`는 “블로커”에 가깝습니다. 회의가 부차적인 주제로 확장될 때 핵심 문제로 되돌리는 표현입니다.

### 5. 배포 후 지표 비교

**영어:** If the metric drifts after deployment, we'll compare it with the pre-release baseline.

**한국어 뜻:** 배포 후 지표가 기준에서 벗어나면 배포 전 기준선과 비교하겠습니다.

**설명:** 실현 가능한 미래 조건이므로 `If + 현재형, will + 동사원형` 구조를 사용합니다. `compare A with B`는 A와 B를 비교한다는 뜻입니다. `metric`은 “메트릭”, `baseline`은 “베이스라인”에 가깝습니다. 배포 이후 수치 변화를 평가하고 원인을 조사할 때 사용합니다.
