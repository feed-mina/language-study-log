# 실무 영어 5문장: 범위 합의와 오류 대응

오류 메시지 개선, 작업 범위 합의, 단기·장기 비용 비교, 미해결 질문 기록, 롤백 가능성 확인에 활용할 수 있는 영어 표현을 연습합니다.

## 전체 학습 항목

### 1. 오류 메시지 개선

**I'm adding more context to the error message so the next failure is easier to diagnose.**

- 뜻: 다음 오류를 더 쉽게 진단할 수 있도록 오류 메시지에 더 많은 맥락 정보를 추가하고 있습니다.
- 설명: `I'm adding`은 현재 진행 중인 작업을 나타내고, `so + 주어 + 동사`는 목적이나 결과를 설명합니다. `context`는 “컨텍스트”, `diagnose`는 “다이어그노즈”에 가깝게 발음합니다. 오류 메시지에 원인 파악에 필요한 정보를 보강할 때 사용합니다.

### 2. 작업 범위 합의

**Before estimating the work, we need to agree on what is out of scope.**

- 뜻: 작업량을 산정하기 전에 범위에서 제외되는 항목에 합의해야 합니다.
- 설명: `before + 동명사`는 “~하기 전에”, `what is out of scope`는 `agree on`의 목적어 역할을 하는 명사절입니다. `estimating`은 “에스터메이팅”, `out of scope`는 “아웃 어브 스코프”에 가깝습니다. 요구사항이나 일정 논의에서 제외 범위를 명확히 할 때 사용합니다.

### 3. 단기·장기 비용 비교

**The proposed shortcut would save time now, but it could increase maintenance costs later.**

- 뜻: 제안된 지름길은 지금 시간을 절약할 수 있지만, 나중에 유지보수 비용을 늘릴 수도 있습니다.
- 설명: `would`와 `could`는 예상되는 효과와 가능성을 신중하게 표현하고, `but`은 단기 이점과 장기 비용을 대비합니다. `proposed`는 “프러포즈드”, `maintenance`는 “메인터넌스”에 가깝습니다. 빠른 해결책의 장단점을 검토할 때 사용합니다.

### 4. 미해결 질문 기록

**Let's record the unresolved questions and revisit them after the test results are available.**

- 뜻: 미해결 질문을 기록하고 테스트 결과가 나오면 다시 검토합시다.
- 설명: `Let's + 동사원형` 뒤에 `record`와 `revisit`이 병렬로 연결됩니다. 미래 상황을 말해도 `after`절에는 현재형 `are`를 씁니다. `unresolved`는 “언리졸브드”, `revisit`은 “리비짓”에 가깝습니다. 회의에서 보류한 쟁점을 후속 검토 항목으로 남길 때 사용합니다.

### 5. 롤백 가능성 확인

**The rollback plan depends on whether the data change can be reversed safely.**

- 뜻: 롤백 계획은 데이터 변경을 안전하게 되돌릴 수 있는지에 달려 있습니다.
- 설명: `depend on whether + 문장`은 “~인지 여부에 달려 있다”라는 뜻입니다. `can be reversed`는 조동사가 포함된 수동태입니다. `depends`는 “디펜즈”, `reversed`는 “리버스트”에 가깝습니다. 배포 전에 데이터 변경의 복구 가능성을 확인할 때 사용합니다.
