# 실무 영어 5문장: 기준 합의부터 오류 조건과 데모 검증까지

작업을 시작하기 전에 완료 기준을 확인하고, 동시 처리에서 발생하는 오류를 설명하며, 일정 조건과 우선순위를 조율하고, 변경된 흐름을 데모로 검증하는 실무 영어 표현을 연습합니다.

## 전체 학습 항목

### 1. 완료 기준 확인

**영어 문장:** I'd like to make sure we're aligned on the acceptance criteria before I start.

**한국어 뜻:** 시작하기 전에 완료 기준에 대해 서로 같은 이해를 하고 있는지 확인하고 싶습니다.

**설명:** 문법: I'd like to는 정중하게 의사를 밝히는 표현이고, make sure 뒤에는 확인할 내용을 나타내는 절이 옵니다. be aligned on은 ‘~에 대해 의견이나 이해가 일치하다’라는 뜻입니다. 발음: we're aligned는 ‘위어 얼라인드’, acceptance criteria는 ‘액셉턴스 크라이티어리아’에 가깝습니다. 사용: 구현을 시작하기 전에 완료 조건이나 검수 기준을 확인할 때 씁니다.

### 2. 오류 발생 조건 설명

**영어 문장:** The issue only occurs when multiple requests are processed at the same time.

**한국어 뜻:** 이 문제는 여러 요청이 동시에 처리될 때만 발생합니다.

**설명:** 문법: occurs는 issue와 수가 맞는 3인칭 단수 현재형이고, are processed는 요청이 처리되는 수동태입니다. at the same time은 ‘동시에’라는 뜻입니다. 발음: occurs는 ‘어커즈’, multiple requests는 ‘멀터플 리퀘스츠’에 가깝습니다. 사용: 오류가 나타나는 구체적인 조건을 개발자나 회의 참석자에게 설명할 때 씁니다.

### 3. 조건부 일정 제시

**영어 문장:** I can implement the change today, provided that the requirements remain unchanged.

**한국어 뜻:** 요구사항이 변경되지 않는다는 조건이라면 오늘 변경 사항을 구현할 수 있습니다.

**설명:** 문법: provided that은 ‘~라는 조건이라면’이라는 조건 접속사입니다. remain + 형용사 unchanged는 ‘변경되지 않은 상태로 유지되다’라는 뜻입니다. 발음: provided that은 ‘프로바이디드 댓’, requirements는 ‘리콰이어먼츠’에 가깝습니다. 사용: 일정이 성립하기 위한 전제 조건을 분명하게 제시할 때 씁니다.

### 4. 우선순위 조정

**영어 문장:** Could we move this item to the next sprint and focus on the blocker first?

**한국어 뜻:** 이 항목은 다음 스프린트로 옮기고, 진행을 막는 문제부터 처리할 수 있을까요?

**설명:** 문법: Could we + 동사원형은 함께 결정할 사항을 정중하게 제안합니다. move A to B는 A를 B로 옮기다, focus on은 ~에 집중하다라는 뜻입니다. 발음: move this item은 자연스럽게 이어 말하고, blocker는 ‘블라커’에 가깝습니다. 사용: 선택적인 작업보다 현재 진행을 막는 문제를 우선 처리하자고 제안할 때 씁니다.

### 5. 데모 검증 준비

**영어 문장:** I'll prepare a short demo so everyone can verify the updated workflow.

**한국어 뜻:** 모두가 변경된 작업 흐름을 확인할 수 있도록 짧은 데모를 준비하겠습니다.

**설명:** 문법: I'll은 I will의 줄임말이며 앞으로 할 일을 나타냅니다. so + 주어 + can은 ‘~할 수 있도록’이라는 목적을 설명합니다. 발음: verify는 ‘베러파이’, updated workflow는 ‘업데이티드 워크플로’에 가깝습니다. 사용: 변경 사항을 회의나 리뷰에서 직접 확인할 수 있도록 시연을 준비하겠다고 말할 때 씁니다.
