# 실무 영어 5문장 — 데이터 점검과 단계적 대응

데이터 불일치 조사, 외부 의존성을 고려한 일정 산정, 오류 에스컬레이션, 피드백 구체화, 핵심 기능 우선 출시 상황에서 사용할 수 있는 실무 영어 표현 5개입니다.

대표 말하기 문장: **The numbers don't match the source data, so I'm checking the transformation logic.**  
한국어 뜻: 수치가 원본 데이터와 일치하지 않아서 변환 로직을 확인하고 있습니다.

## 전체 학습 항목

### 1번

**영어 문장:** The numbers don't match the source data, so I'm checking the transformation logic.

**한국어 뜻:** 수치가 원본 데이터와 일치하지 않아서 변환 로직을 확인하고 있습니다.

**설명:** 문법: don't match는 '일치하지 않는다', be checking은 현재 진행 중인 조사를 나타냅니다. so는 원인에 따른 결과를 연결합니다. 발음: numbers는 '넘버즈', transformation은 '트랜스퍼메이션'에 가깝고, source data는 두 단어를 자연스럽게 이어 말합니다. 맥락: 집계값이나 화면의 수치가 원본과 다를 때 현재 확인 중인 지점을 설명하는 표현입니다.

### 2번

**영어 문장:** Before we commit to a deadline, we need to account for the external dependency.

**한국어 뜻:** 마감 일정을 확정하기 전에 외부 의존 요소를 고려해야 합니다.

**설명:** 문법: commit to는 '~을 확정적으로 약속하다', account for는 '~을 고려하다'라는 구동사입니다. Before가 이끄는 절에서는 미래 의미라도 현재형 commit을 사용합니다. 발음: deadline은 '데드라인', dependency는 두 번째 음절에 힘을 주어 '디펜던시'에 가깝게 말합니다. 맥락: 다른 작업이나 승인에 일정이 좌우될 때 성급한 완료 약속을 피하는 표현입니다.

### 3번

**영어 문장:** If the issue persists after the restart, I'll escalate it and include the relevant logs.

**한국어 뜻:** 재시작 후에도 문제가 계속되면 상위 담당자에게 전달하고 관련 로그를 첨부하겠습니다.

**설명:** 문법: 미래 조건을 나타내는 if절에는 현재형 persists를 쓰고, 결과절에는 will을 사용합니다. escalate는 해결 권한이 있는 상위 단계로 문제를 전달한다는 뜻입니다. 발음: persists는 '퍼시스츠', relevant는 첫 음절에 힘을 주어 '렐러번트'에 가깝습니다. 맥락: 기본 조치 후에도 오류가 남을 경우 다음 대응 계획을 알릴 때 사용합니다.

### 4번

**영어 문장:** Could you point out which part of the proposal needs more detail?

**한국어 뜻:** 제안서의 어느 부분에 더 자세한 설명이 필요한지 짚어 주실 수 있나요?

**설명:** 문법: Could you는 정중한 요청이고, which part of the proposal needs more detail은 point out의 내용을 나타내는 간접의문문이라 평서문 어순을 사용합니다. 발음: point out은 연결해 '포인타웃', proposal은 두 번째 음절에 힘을 주어 '프러포절'에 가깝습니다. 맥락: 막연한 수정 요청을 받았을 때 필요한 보완 지점을 구체적으로 확인하는 표현입니다.

### 5번

**영어 문장:** We can release the core functionality now and address the refinements separately.

**한국어 뜻:** 핵심 기능은 지금 출시하고 세부 개선 사항은 별도로 처리할 수 있습니다.

**설명:** 문법: can 뒤에는 동사원형 release와 address가 and로 병렬 연결됩니다. 여기서 address는 문제나 과제를 '다루다'라는 뜻입니다. 발음: functionality는 '펑크셔낼러티', refinements는 '리파인먼츠'에 가깝습니다. 맥락: 필수 기능을 먼저 제공하고 완성도를 높이는 작업은 후속 단계로 분리하자고 제안할 때 사용합니다.
