# 실무 영어 5문장 — 배포 확인·로그 비교·일정 위험·회의 합의·장애 후속 조치

배포 전 확인, 오류 로그 비교, 일정 위험 공유, 회의 중 이견 정리, 장애 종료 조건을 자연스럽게 말하는 실무 영어 표현 5개를 연습합니다.

## 전체 학습 항목

### 1. 배포 전 확인

**Before we deploy, let's confirm that the rollback procedure has been tested.**  
배포하기 전에 롤백 절차가 테스트되었는지 확인합시다.

문법: Before + 주어 + 동사는 ‘~하기 전에’, has been tested는 현재완료 수동태로 테스트 완료 상태를 나타냅니다. 발음: rollback은 ‘롤백’, procedure는 ‘프러시저’에 가깝습니다. 상황: 배포 직전 복구 절차가 실제로 검증되었는지 확인할 때 씁니다.

### 2. 로그 비교

**The error pattern differs from what we saw in the previous logs.**  
오류 패턴이 이전 로그에서 본 것과 다릅니다.

문법: differ from은 ‘~와 다르다’, what we saw는 ‘우리가 본 것’이라는 명사절입니다. 발음: differs는 ‘디퍼즈’, previous는 ‘프리비어스’에 가깝습니다. 상황: 현재 오류가 과거 사례와 다른 양상을 보인다고 설명할 때 씁니다.

### 3. 일정 위험 공유

**If this dependency slips, the delivery date may need to be adjusted.**  
이 의존 작업이 지연되면 납기일을 조정해야 할 수도 있습니다.

문법: 미래 가능성을 말해도 if절에는 현재형 slips를 쓰며, may need to be adjusted는 ‘조정될 필요가 있을 수 있다’라는 수동 표현입니다. 발음: dependency는 ‘디펜던시’, adjusted는 ‘어저스티드’에 가깝습니다. 상황: 선행 작업 지연이 전체 일정에 영향을 줄 수 있음을 공유할 때 씁니다.

### 4. 회의 이견 정리

**It sounds like we agree on the goal but not on the implementation details.**  
목표에는 동의하지만 구현 세부 사항에는 의견이 다른 것 같습니다.

문법: It sounds like + 문장은 단정하지 않고 판단을 부드럽게 제시합니다. agree on은 ‘~에 합의하다’입니다. 발음: implementation은 ‘임플러멘테이션’, details는 ‘디테일즈’에 가깝습니다. 상황: 회의에서 큰 방향은 같지만 구체적인 방법에는 이견이 있을 때 씁니다.

### 5. 장애 후속 조치

**I'll keep the incident open until we've confirmed that the service is stable.**  
서비스가 안정적이라는 것을 확인할 때까지 장애 건을 종료하지 않겠습니다.

문법: keep + 목적어 + 형용사는 ‘목적어를 어떤 상태로 유지하다’, until은 ‘~할 때까지’입니다. 현재완료 we've confirmed는 확인이 완료되는 시점을 강조합니다. 발음: incident는 ‘인시던트’, confirmed는 ‘컨펌드’에 가깝습니다. 상황: 일시적으로 회복됐더라도 안정성이 확인될 때까지 장애 처리를 계속할 때 씁니다.
