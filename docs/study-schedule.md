# 학습 달력과 회복 큐

## 사용 흐름

1. 주간/월간 달력에서 날짜를 선택해 공부 분량, 일정 완료율, 복습 도래 카드 수를 확인합니다.
2. `놓친 공부 채우기`에서 기간·언어·제목을 검색합니다. 서버에서 5개씩 가져오며 전체 건수·시간은 페이지와 별도로 집계합니다.
3. 항목을 선택해 날짜와 선택적 시작 시각을 배정합니다. 여러 개는 차례로 배정되고, 실패 항목의 선택·입력은 남습니다. 개별 `오늘로 가져오기`는 시간 미정으로 배정합니다.
4. 선택한 하루에서 시간 미정과 시간 지정 계획을 확인하고, 기존 학습 완료 기록·완료 취소·자료 열기를 이용합니다.
5. 도래한 복습 카드를 선택해 복습 세션으로 배정합니다. 답을 확인하고 난이도를 평가하면 FSRS가 다음 복습일을 계산합니다. 카드 평가를 모두 저장하면 세션이 완료됩니다.

하루 목표는 기본 60분이며 10~600분으로 바꿀 수 있습니다. 목표 초과는 안내이고 저장을 강제로 막지 않습니다. 지정 시각이 겹치거나 자정을 넘으면 서버에서 저장을 거절합니다. 보관한 계획을 복원하면 원래 날짜에 시간 미정으로 돌아옵니다.

## 파일과 데이터

- `app/components/StudySchedule.tsx`: 일정 화면과 복습 진행 조율.
- `StudyCalendar.tsx`, `DayAgenda.tsx`, `RecoveryQueue.tsx`: 달력, 하루 상세, 서버 페이지 탐색.
- `app/api/dashboard/schedule/route.ts`: 기존 Google Access/관리자 인증을 재사용하는 일정·복습 API. 쓰기 요청은 16 KiB 제한.
- `worker/study-schedule.ts`: 일별 요약, 회복 큐, 시간 변경, 복습 세션과 평가.
- `worker/study-cycle.ts`: 기존 원본 연결·계획 이력을 유지하는 재계획. 새 일정 경로의 상태 검증과 시각 배정을 같은 D1 배치에서 처리.
- `worker/schedule-schema.ts`, `drizzle/0007_study_schedule.sql`: 추가 테이블, 중복 카드 배정과 겹치는 시각을 막는 제약, 복습 평가의 원자적 저장 트리거.

기존 `study_plans` 컬럼은 다시 쓰지 않고 `study_plan_slots`에 선택적 시각을 둡니다. `review_sessions`의 사용자 배정일은 `study_cards.due`와 다릅니다. 오답 재풀이·복습 메모는 기존 별도 기능을 유지합니다. `private-cycle-work/public/private/schedule.html`의 주간·월간 및 선택일 상세 상호작용을 참고했으며 회사 일정/DB는 복제하지 않습니다.

## 적용과 호환

새 API는 기존 앱과 같은 방식으로 필요한 테이블을 `CREATE IF NOT EXISTS`로 준비하므로 첫 요청에도 작동합니다. 운영 마이그레이션 이력에는 0007을 기존 방식으로 적용할 수 있으며 새 스키마 준비 후에도 다시 적용할 수 있습니다. 기존 0000~0006 마이그레이션의 재실행을 의미하지 않습니다. 0007에는 데이터 삭제·초기화·기존 테이블 ALTER가 없습니다.

메인 대시보드는 `recovery=none`으로 이전 미완료 전체 배열을 요청하지 않습니다. 기존 API 이용자를 위한 기존 응답은 유지하며 새 큐는 날짜+ID 커서로 페이지를 탐색합니다. 복습 카드 목록은 현재 도래·미배정 50장, 세션은 최대 20장으로 제한하며 배정 후 다음 후보를 보여줍니다.

클라이언트는 실패한 쓰기의 요청 ID를 재사용합니다. 복습 카드 상태, 평가 기록, 세션 완료와 요청 영수증은 같은 D1 트랜잭션으로 저장합니다. 기존 별도 관리자 복습 API 동작은 변경하지 않았습니다.

## 검증

- `npm run check`: lint, 타입 검사, 53개 테스트, 프로덕션 빌드.
- 실제 D1 시뮬레이터: 전체 마이그레이션 적용 및 새 스키마 재준비, 105개 커서 탐색, 빈 검색 결과, 이전 빈 updated_at, 시간 충돌 시 원본 재계획 롤백, 동시 재계획, 중복 카드 배정, 같은 평가 재시도·동시 요청, 세션 완료·취소, KST와 윤년.
- 빌드된 Worker를 로컬 DB로 실행한 브라우저 검증: 주간/월간, 검색·페이지 탐색, 시각 지정 재계획, 실제 FSRS 평가, 1280px/420px 가로 넘침 없음. 로컬 브라우저 검증에서 로그인 상태 응답만 대체했고 쓰기는 로컬 테스트 토큰으로 기존 인증 경로를 통과했습니다. 운영 Google Access 인증은 기존 단위 테스트를 유지합니다.
- 기존 Vite 플러그인에 포함된 로컬 런타임은 현재 호환 날짜보다 오래되어 빌드 결과를 프로젝트의 Wrangler 4.127.1로 검증했습니다. `CLOUDFLARE_REMOTE_BINDINGS=false`는 개발 시 원격 바인딩을 끄는 선택 사항입니다.
